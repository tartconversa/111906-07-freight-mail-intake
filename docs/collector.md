# 采集程序说明(collector)

业务采集程序:从演练 IMAP 邮箱只读领取邮件原件,按原件内容归到运输批次,向本地入场
交接台提交有凭据的到货资料,并给收货组留下可查的缺件、扣留原因与待核实项。
只依赖 Python 标准库;不读取来源的 fixtures、服务内存或检查接口。

## 数据流

```
IMAP(只读) ──> 原件落库(MIME 哈希) ──> 附件单证解析 ──> 按内容归批次 ──> 版本裁决
                                                              │
交接台(先查后交) <── 交接/停交计划 <── 箱状态(应有/到货/放行) <──┘
```

## 身份与归属口径

- **邮件身份 = MIME 字节哈希**。UID 只在当前 UIDVALIDITY 内有效;世代变化(邮箱重建)后
  本地 UID 记录作废并整文件夹重扫。邮件移动到归档文件夹后字节不变,哈希相同,只补记
  新位置,不重复落账。
- **Message-ID 不作唯一性**:同一 Message-ID 可能随不同转发夹带不同单证(如旧批次箱单),
  内容不同即不同原件,各自归各自批次。
- **归属只看附件内容**:`documents.json` 里的 `carrier`/`shipment`/`boxes` 决定归属;
  主题、发件人、文件名一律不作依据。发件人白名单(`--read-senders`)仅限定读取范围。
- 同一文件名可以反复出现;附件按内容哈希去重。一份放行书覆盖多箱时,每箱各自保留
  与该单证的关联(箱级状态独立计算)。

## 单证裁决

- `manifest` 定义批次应有箱范围,取最高版本;同版不同内容即冲突,整批阻塞待核。
- 同一 `carrier/shipment/box` 的 `release` 与 `hold` 按 `version` 决出当前状态;
  同版相反结论(release 与 hold 同版本)为冲突,该箱阻塞待核。
- **裁决与收信顺序无关**:晚到的旧版本单证不能推翻已生效的高版本扣留/放行。
- `arrival` 独立决定实际到货。缺明确 release 的箱不可交。
- 无法解析、无单证附件、批次无箱单、箱号在箱单外的原件进入待人工核实(`review`),
  不从主题猜结论;部分待核项在依据补齐(如箱单后到、更高版本到达)后自动了结。
- 人工了结:`review-resolve <编号> --choose <内容哈希前缀>` 明确选定一份内容,
  其余内容标记作废,绝不按到达先后取舍。

## 交接与停交

- 每轮先 `GET /handoff`、`GET /stop` 对齐远端,再只提交缺口;reference 确定性生成
  (`handoff:承运:批次:箱`、`stop:承运:批次:箱`),断线重连、丢响应(远端先保存后 503)、
  来源重启清空记录,都靠查询对齐,同一箱不会被安排两次入场。
- 只有"箱单内 + 已到货 + 当前放行 + 无冲突"的箱才提交交接,evidence 为单证/邮件哈希摘要。
- 已交接的箱补到扣留(或陷入冲突)时,自动 `POST /stop` 并每轮查询现场确认状态;
  未确认的停交在 `stops` 中持续可见。已停交的箱不自动重交,需收货组处置后人工处理。
- 已到货但被扣留的箱在 `detained` 中列明,交收货组现场处置,不得入场。

## 状态与原件保管

- 采集程序自有状态在 `--data-dir`(默认 `var/`):SQLite(`collector.db`)+ 受限原件目录
  (`store/`,0700;原件文件 0600)。原始 MIME 与附件完整保留,可哈希定位。
- 所有查询命令输出脱敏(邮箱本地部分、长数字串打到 `***`);联系方式只留在受限原件里。
- 来源服务重启不影响本状态;交接台记录被清空时,本地已交接记录标记"查无记录"并重新提交。

## 演练验证(对应来源阶段)

```bash
python3 -m source.app --port 8765 &          # 阶段 0:两箱放行,仅 BX1 到货
python3 -m collector collect                 # → BX1 交接,BX2 缺到货回报
curl -X POST -H 'X-Operator: local-operator' -H 'Content-Type: application/json' \
     -d '{"stage":1}' http://127.0.0.1:8765/__control   # 检查人员推进:重建+移动+扣留+旧转发
python3 -m collector collect                 # → 只对 2 封新原件落账;BX1 停交待确认;旧批次单列
curl -X POST -H 'X-Operator: local-operator' -H 'Content-Type: application/json' \
     -d '{"stage":2}' http://127.0.0.1:8765/__control   # 现场确认停交
python3 -m collector collect && python3 -m collector stops   # → 停交已确认
```

`__control` 是检查人员接口,采集程序自身不调用。自动化验证见
`tests/test_collector.py`(真实 IMAP 会话与交接接口)与 `tests/test_collector_units.py`。

## 已知限制

- 同一箱"停交已确认后再次放行"不会自动重交(防止重复入场),需人工核查后清理本地记录。
- 邮件从文件夹消失(非移动)不主动侦测;以每次重扫见到的新位置为准。
- 单证字段之外的自然语言正文不参与裁决,仅随原件保存。
